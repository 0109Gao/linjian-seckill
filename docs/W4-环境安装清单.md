# W4-0 环境安装：WSL2 + Docker Desktop（全装到 D 盘）

> 本文档是给**你手动执行**的操作清单。原因：代理进程无管理员权限，且 `wsl.exe`
> 被沙箱程序黑名单拦截（安全中心限制，代理侧不可绕过）。
>
> 脚本已就绪，位于 `scripts/`，本文档只负责「什么时候、在哪个窗口、粘哪一行」。

---

## 0. 装前事实核对（2026-10-30 实测）

| 项 | 实测值 | 说明 |
|---|---|---|
| 系统 | Windows 11 家庭版 build 26300 | 家庭版无 Hyper-V，WSL2 走 `VirtualMachinePlatform` |
| CPU | i5-1240P，`HypervisorPresent=True` | **虚拟化已在硬件层生效，不需要进 BIOS 开 VT-x** |
| `VirtualizationFirmwareEnabled` | `False` | 假阳性：被运行中的 hypervisor 接管后该 CIM 字段必然返回 False |
| WSL 现状 | `LxssManager` 服务不存在、`HKCU\...\Lxss` 无键 | 确认从未安装，全新安装 |
| Docker 现状 | `D:\Docker\app`、`C:\Program Files\Docker` 均不存在 | 全新安装 |
| 磁盘 | C 剩 124.2 GB / D 剩 207.5 GB | 够用；WSL 发行版与 Docker 数据均会 relocate 到 D |

**目标落盘位置**

| 内容 | 位置 |
|---|---|
| Ubuntu 发行版 VHDX | `D:\WSL2\app` |
| Docker Desktop 程序 | `D:\Docker\app` |
| Docker 镜像/容器/卷 | `D:\Docker\data` |

## 阶段 1：启用 WSL 核心（需重启）

**开一个「管理员」PowerShell**（开始菜单搜 PowerShell → 右键「以管理员身份运行」），粘贴：

```powershell
cd "D:\WorkBuddy\项目\linjian-seckill\scripts"
powershell -NoProfile -ExecutionPolicy Bypass -File .\install-wsl2.ps1 -Phase Core
```

预期输出：

```
[1/3] enabling WSL and Virtual Machine Platform features
[2/3] installing WSL core (no distribution yet)
[3/3] setting default version to 2
DONE. REBOOT NOW, then run:  .\install-wsl2.ps1 -Phase Distro
```

脚本分三步：DISM 启用两个 Windows 功能 → 装 WSL 本体 → 设默认版本 2。

### 两个会让人误判的卡点

**卡点一：DISM 停在 6% 附近很久，这是正常的。**
那个百分比是「工作量」不是「时间进度」。6% 上下正在注册组件并写 CBS 事务日志，
停十几分钟不稀奇。判断真死还是假死，看这三个进程是否还在：
`dism.exe`、`TiWorker.exe`、`TrustedInstaller.exe`。都在 = 在干活。
另一个硬指标是 `C:\Windows\Logs\CBS\CBS.log` 的最后写入时间，还在往前推进就是在工作。

**卡点二：第 2 步从 GitHub 下载 350 MB 的 WSL 包，网络不通时会「假活」而不是报错。**
TCP 握手成功、连接显示 `ESTABLISHED`，但数据被阻断，命令既不返回也不超时。
2026-10-30 本机实测：**挂了 62 分钟，进程累计读取 0 MB、写入 0 MB、CPU 只用 1.6 秒**，
12 秒采样下载量为 0 字节。这属于挂死，继续等不会有结果，`Ctrl+C` 掉即可。

脚本现在会先探测 `github.com`，不通就在第 2 步直接跳过并给出提示：

```
[2/3] installing WSL core (no distribution yet)
  github.com is unreachable from here - skipping.
  The 350 MB WSL MSI cannot be downloaded. Use the 16 MB legacy kernel:
    install-wsl2.ps1 -Phase Kernel    (after reboot)
```

**看到 DONE 后立刻重启**，此时 WSL 功能尚未生效，任何 `wsl` 命令都会报「子系统未安装」。
重启前可以核对一个信号：`HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Component Based Servicing\RebootPending`
键存在 = 两个功能都已启用成功，只差重启。

## 阶段 1.5：装 WSL 内核（仅当阶段 1 跳过了 GitHub 下载）

内核包只有 **16 MB**，走微软自己的 Azure 存储，不经过 GitHub。

**下载**（普通窗口即可，不用管理员）：

```powershell
New-Item -ItemType Directory -Force -Path D:\WSL2\pkg | Out-Null
curl.exe -L -o D:\WSL2\pkg\wsl_update_x64.msi https://wslstorestorage.blob.core.windows.net/wslblob/wsl_update_x64.msi
(Get-Item D:\WSL2\pkg\wsl_update_x64.msi).Length
```

最后一行应输出 `17104896`。如果不是这个数，说明没下完整，删掉重下。

**重启后安装**：

```powershell
cd "D:\WorkBuddy\项目\linjian-seckill\scripts"
powershell -NoProfile -ExecutionPolicy Bypass -File .\install-wsl2.ps1 -Phase Kernel
```

> 为什么不硬啃那 350 MB：GitHub 镜像 `ghfast.top` 实测只有 **49 KB/s**，下完要两小时；
> 16 MB 的内核包 4 分钟搞定，效果一样。

## 阶段 2：装 Ubuntu 并搬家到 D 盘（重启后执行）

**重启后，重新开「管理员」PowerShell**，粘贴：

```powershell
cd "D:\WorkBuddy\项目\linjian-seckill\scripts"
powershell -NoProfile -ExecutionPolicy Bypass -File .\install-wsl2.ps1 -Phase Distro
```

脚本做四件事：装 Ubuntu → `wsl --shutdown` → `wsl --manage Ubuntu --move D:\WSL2\app` → 校验。

> 脚本里的安装命令带了 `--legacy`，让发行版挂到系统内置运行时上，不去 GitHub 拉 WSL 本体
> ——否则会重演阶段 1 那个「挂 62 分钟零字节」的场景。旧版本若拒绝该参数，脚本会自动回退重试。

预期输出末尾：

```
WSL2 ready. Distribution data now under D:\WSL2\app
```

耗时 3~10 分钟（Ubuntu 镜像约 600 MB）。

### 唯一的交互点

`--no-launch` 跳过了首次启动，所以**发行版还没有 Linux 用户名/密码**。
用下面命令完成初始化（只需一次）：

```powershell
wsl -d Ubuntu
```

首次进入会让你输入 UNIX username 与 password（密码输入时不显示字符，正常）。
创建完自动进入 shell，输入 `exit` 退出。

### 验证

```powershell
wsl --status
wsl --list --verbose
```

必须满足：`默认版本: 2`，且 `Ubuntu` 那行 `VERSION` 为 `2`。
再确认数据不在 C 盘：

```powershell
Get-ChildItem 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Lxss' |
  ForEach-Object { (Get-ItemProperty $_.PSPath).BasePath }
```

应输出 `D:\WSL2\app`（或 `D:\WSL2\app\...`）。

## 阶段 3：装 Docker Desktop（阶段 2 验证通过后）

仍是**管理员** PowerShell：

```powershell
cd "D:\WorkBuddy\项目\linjian-seckill\scripts"
powershell -NoProfile -ExecutionPolicy Bypass -File .\install-docker.ps1
```

安装器参数（已固化在脚本里）：

| 参数 | 值 | 作用 |
|---|---|---|
| `--installation-dir` | `D:\Docker\app` | 程序装到 D 盘 |
| `--wsl-default-data-root` | `D:\Docker\data` | 镜像/容器/卷落 D 盘 |
| `--backend=wsl-2` | — | 锁死后端，避免在这台机器上误选 Hyper-V（家庭版也没有） |
| `--accept-license` | — | 免交互 |

耗时 5~15 分钟，安装包约 600 MB。**期间不要关窗口**。

### 装完必须做的三件事

1. **启动一次 Docker Desktop**（开始菜单 → Docker Desktop），走完首启向导，
   接受服务条款，跳过登录/账号（可选 Skip）。
2. **确认磁盘位置**：Settings → Resources → Advanced → `Disk image location`
   应为 `D:\Docker\data`。若显示 C 盘，手动改。
3. **重登录一次**（注销再登录，或重启），使 `docker-users` 组成员身份生效。

### 验证

```powershell
docker version
docker info --format '{{.ServerVersion}} | {{.OSType}} | {{.DockerRootDir}}'
docker run --rm hello-world
```

三条全过 = Docker 可用。`docker run` 首次会拉镜像，慢是正常的。

## 常见失败与处置

| 现象 | 原因 | 处置 |
|---|---|---|
| `wsl --install` 报 `0x800701bc` | WSL 内核未更新 | 装 `wsl.2.x.x.x.x86_64.msi`（微软 WSL releases 页）后重试 |
| `wsl -l -v` 显示 VERSION=1 | 默认版本没设成 2 | `wsl --set-default-version 2` 后 `wsl --set-version Ubuntu 2` |
| `--move` 报 `参数无效` | WSL < 2.0.4 | 用脚本提示的 `--export` + `--import-in-place` 兜底 |
| `--move` 报目标非空 | `D:\WSL2\app` 已有文件 | 清空该目录后重跑阶段 2 |
| Docker 启动卡 `Starting...` | WSL 内核或 vmp 未就绪 | 重启一次机器；仍失败则 `wsl --update` |
| `docker` 命令提示拒绝访问 | 未加入 docker-users 组 | 注销重登录；或管理员执行 `net localgroup docker-users %USERNAME% /add` |
| Docker 首启提示 WSL 版本过旧 | 内核旧 | `wsl --update` 后重启 Docker Desktop |
